# ADR 0008 · Runtime Java 25 (en lugar de Java 21)
Estado: aceptada (pendiente de confirmar con medición)

**Contexto.** El spike eligió Java 21 por ser LTS. Al saturar una réplica a ~500 req/s, `-Djdk.tracePinnedThreads` mostró **hilos virtuales atascados**
(`reason:MONITOR`) en el cliente HTTP de Apache del SDK de AWS (`AbstractConnPool.get`, `PoolingHttpClientConnectionManager.releaseConnection`).
En Java 21 un bloque `synchronized` fija el hilo virtual a su hilo portador; cuando SQS se atrasa se agotan los portadores, el pod no atiende ni sus
sondas de salud y Kubernetes lo reinicia. El servicio de referencia corre Java 25, donde JEP 491 elimina esa fijación.
**Decisión.** Compilar y ejecutar con Java 25 (Temurin 25) y Spring Boot 3.5.16 (3.4.x no declara soporte para Java 25).
**Consecuencias.** La PoC queda alineada con el runtime observado en producción. Se mantienen los virtual threads solo si la medición muestra que no empeoran
frente a hilos de plataforma (producción no los configura). Ver `docs/as-is-to-be-configuracion.md`.

## Actualización · hilos de plataforma
Comparación de una réplica a 500 req/s durante 120 s, 2 CPUs, generador dentro del clúster:

| Runtime y hilos | Errores | p95 | p99 |
|---|---|---|---|
| Java 21 + virtual threads | 79 % (colapsó) | 5001 ms | 5001 ms |
| Java 21 + hilos de plataforma | 0 % | 1,8 ms | 315 ms |
| Java 25 + virtual threads | 0 % (2 corridas) | 392 / 1,8 ms | 814 / 287 ms |
| Java 25 + hilos de plataforma | 0 % | 1,8 ms | 366 ms |

**Decisión final:** Java 25 con **hilos de plataforma** (Tomcat por defecto), que es lo observable en el servicio de referencia (sin ajustes de hilos en su configuración;
no se pudo verificar el despliegue en ejecución, es una inferencia). Se retira `spring.threads.virtual.enabled`. El resto de la variación entre corridas (p99 287–814 ms con la misma
configuración) se atribuye al entorno compartido.
